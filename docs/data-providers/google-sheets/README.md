# Google Sheets provider

The Google Sheets provider stores a competition in three tabs: `Sessions`, `Participants`, and `Matches`. The header spelling and order are part of the Apps Script API contract; `setupSheets()` creates the tabs and writes the headers when they are missing or differ.

## Workbook schema

### `Sessions`

| Column | Meaning |
| --- | --- |
| `session_id` | Stable session ID, generated by Apps Script (`SES-…`). |
| `name` | Competition name. |
| `event_date` | Event date as text/date value; may be empty. |
| `location` | Location; may be empty. |
| `status` | `in_progress` or `completed` for sessions managed by the app. |
| `format` | `single_elimination` or `team_single_elimination`. Team sessions store each pair as one participant name joined with ` & `. |
| `created_at` | ISO timestamp written by Apps Script. |
| `updated_at` | ISO timestamp, refreshed when the session is changed. |

### `Participants`

| Column | Meaning |
| --- | --- |
| `participant_id` | Stable participant ID, generated by Apps Script (`PAR-…`). |
| `session_id` | Owning session ID from `Sessions`. |
| `name` | Participant name. For team sessions, the app presents two participants as one team. |
| `seed` | Positive bracket seed/order. |
| `created_at` | ISO timestamp written by Apps Script. |

### `Matches`

| Column | Meaning |
| --- | --- |
| `match_id` | Stable match ID, generated by Apps Script (`MAT-…`). |
| `session_id` | Owning session ID from `Sessions`. |
| `round` | One-based bracket round. |
| `match_number` | One-based match number in that round. |
| `participant1_id` | First participant slot; empty until assigned. |
| `participant2_id` | Second participant slot; empty until assigned. |
| `score1` | First participant's score; empty until decided. |
| `score2` | Second participant's score; empty until decided. |
| `winner_id` | Winning participant ID; empty until decided. |
| `status` | `pending`, `completed`, or `bye`. A bye is decided and advances its participant. |
| `next_match_id` | Following match ID; empty for the final. |
| `next_slot` | `participant1`, `participant2`, or empty. |
| `created_at` | ISO timestamp written by Apps Script. |
| `updated_at` | ISO timestamp, refreshed when the match changes. |

## Install and deploy the Apps Script

1. Create a Google spreadsheet and open **Extensions → Apps Script**.
2. Copy [`Code.gs`](Code.gs) into the Apps Script project.
3. In **Project Settings → Script Properties**, add `SPREADSHEET_ID` with the spreadsheet ID. Do not put a real spreadsheet ID in this repository.
4. Run `setupSheets()` once and approve the requested spreadsheet permissions.
5. Deploy the script as a Web app. The app's API proxy must be able to call the deployment URL.
6. Set `APPS_SCRIPT_URL` to that deployment URL for Netlify Functions, or set it for the local `server.js` proxy as described in the root README.

The script handles `listSessions`, `getSession`, `createSession`, `addParticipant`, `updateMatchScore`, and `updateSessionStatus`. The last action updates the existing `Sessions.status` and `updated_at` cells; it does not add columns. Redeploy the Web app after changing the script.

## API payloads

The browser calls the app's `/api/*` proxy. The proxy translates those requests to Apps Script actions:

| App route | Apps Script action |
| --- | --- |
| `GET /api/sessions` | `listSessions` |
| `GET /api/session?session_id=…` | `getSession` |
| `POST /api/sessions` | `createSession` |
| `POST /api/participants` | `addParticipant` |
| `POST /api/matches/score` | `updateMatchScore` |
| `POST /api/sessions/status` | `updateSessionStatus` |

Apps Script returns `{ ok, data }` on success and `{ ok: false, error }` on failure. Do not expose spreadsheet IDs, deployment URLs, or credentials in public issues or commits.
